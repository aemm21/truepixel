👁️ TruePixel: Open-Source AI Image Verification Engine

**Version 3.4.0** — see [CHANGELOG.md](CHANGELOG.md)

TruePixel is a lightweight, private, open-source engine designed to detect synthetic images generated by Artificial Intelligence (Deepfakes, Midjourney, DALL-E, Stable Diffusion).

Unlike commercial detectors that analyze superficial visual imperfections, TruePixel operates under a dual scientific approach: it analyzes pixel geometry and searches for physical anomalies in the Fourier frequency domain that are mathematically impossible for generative diffusion models to replicate seamlessly.

⚠️ CRITICAL NOTICE: TRAINING REQUIRED

🔴 IMPORTANT: TruePixel is an architectural framework. Out of the box, the model weights are initialized randomly.

You must train the model with your own dataset of real and AI-generated images before using verify.py or api.py. Running the model without training will result in random predictions (usually defaulting to "Suspicious" or "Real" because the untrained weights fall in the middle of the sigmoid distribution).

To make TruePixel functional, follow the Training Section below to build your weights file (for example, `truepixel_v2.pth`).

🧠 Dual-Branch Architecture

TruePixel processes each image file through two independent parallel channels before emitting a unified probabilistic judgment:

               ┌─────────────────────────────┐
               │         Input Image         │
               └──────────────┬──────────────┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
     [ Spatial Branch ]            [ Frequency Branch ]
  - Analyzes pixels/textures -    - Fourier Transform (FFT) -
  - ResNet18 (ImageNet)      -    - Spectral Log-Magnitude  -
              │                               │
              └───────────────┬───────────────┘
                              ▼
                  [ Feature Concatenation ]
                              │
                              ▼
                    [ Sigmoid Classifier ]
                              │
                              ▼
                     📊 AI Probability %


Spatial Branch (Visual): A ResNet18 backbone pre-trained on ImageNet, optimized to identify texture artifacts, edge inconsistencies, and local color anomalies.

Frequency Branch (Spectral): Converts the image tensor using a 2D Fast Fourier Transform ($\text{FFT}_{2\text{D}}$). Images created by AI exhibit periodic patterns and geometric spikes in high frequencies due to mathematical upsampling and pixel interpolation.

📦 Repository Structure

The project maintains a clean, modular structure for easy extensibility:

| File | Description |
|---|---|
| `model.py` | Architecture definition of the unified neural network (TruePixelNet). |
| `fourier.py` | Fourier magnitude spectrum core operations optimized in PyTorch. |
| `dataset.py` | Deterministic, recursive data loader tolerant to corrupt images. |
| `config.py` | Centralized configuration: paths, thresholds, limits, CORS, device, and transforms. |
| `checkpoint.py` | Versioned weight saving/loading with backward compatibility for plain `state_dict`. |
| `explain.py` | Explainability: Grad-CAM and colorized spectral map. |
| `train.py` | CLI training with stratified Train/Val/Test split and AUC/F1 metrics. |
| `evaluate.py` | Evaluation with AUC/F1/confusion matrix and threshold sweep on labeled folders. |
| `evaluar_ood.ps1` | PowerShell script to evaluate the model against each OOD generator and build a summary CSV. |
| `verify.py` | CLI tool to evaluate one image (human-readable report or `--json`). |
| `api.py` | FastAPI server with `/health`, CORS, and interactive docs. |
| `tests/` | `pytest` suite (Fourier, model, dataset, metrics, checkpoints, evaluation, and API). |
| `Dockerfile` | Production image with PyTorch CPU and uvicorn. |
| `CHANGELOG.md` | Version history. |

🚀 Quick Start Guide

1. Clone and Install Dependencies

Ensure you have a virtual environment active, and execute:

# Clone the repository
git clone [https://github.com/aemm21/truepixel.git](https://github.com/aemm21/truepixel.git)
cd truepixel

# Install required dependencies
pip install -r requirements.txt


2. Parametric Training (CLI)

Before verifying any images, you need to train the network. Set up your dataset by placing real photos in ./data/reales and AI-generated images in ./data/sinteticas.

You can configure the training process directly from the terminal using arguments:

# Run training with custom hyperparameters
python train.py --epochs 40 --batch_size 16 --lr 0.0003 --val_split 0.20

# Resume after an interruption (same arguments and same --output)
python train.py --resume --output truepixel_v2.pth

# Fine-tune from a checkpoint (resets epoch and optimizer)
python train.py --init truepixel_v2.pth --output truepixel_v3.pth --epochs 3 --lr 0.00001 --batch_size 8

The first training run downloads the ImageNet ResNet18 weights (~45 MB).


Available Parameters:

--dir_reales: Path to the directory containing authentic photos (Default: ./data/reales).

--dir_sinteticas: Path to the directory containing synthetic AI images (Default: ./data/sinteticas).

--epochs: Number of passes through the complete dataset.

--lr: Learning rate for the Adam optimizer.

--val_split: Percentage of images reserved for validation (e.g., 0.20 = 20%).

--test_split: Percentage of images reserved for the final test set (Default: 0.15).

--num_workers: Data loading worker processes (0 = no multiprocessing).

--seed: Random seed for reproducibility (Default: 42).

--output: Name of the generated weights file (Default: truepixel_v1.pth).

--resume: Continues from the checkpoint in --output, restoring epoch, best validation loss, and optimizer state.

--init: Initializes weights from a checkpoint for fine-tuning, resetting epoch and optimizer (cannot be combined with --resume).

The Train/Validation/Test split is **stratified** to preserve class proportions. At the end of training, Accuracy, AUC-ROC, F1, Precision, Recall, and the confusion matrix are reported on the test set.

📏 Evaluation with Metrics

If you have labeled folders (real and AI), `evaluate.py` computes AUC, F1, precision, recall, specificity, and the confusion matrix, and searches for the best decision threshold:

# Evaluate the held-out test set and save predictions
python evaluate.py --dir_reales C:\datasets\ai-real\test\real --dir_sinteticas C:\datasets\ai-real\test\fake --modelo truepixel_v2.pth --csv predictions.csv

Parameters: `--umbral` (0.5 by default), `--json`, `--csv`, `--batch_size`, `--num_workers`, and `--recursivo`.

The threshold sweep is computed on the evaluated set itself; for production, tune the threshold on validation and confirm it on an independent test set.

📈 Reference Results

`truepixel_v2.pth` checkpoint (ResNet18 + Fourier), evaluated on the held-out official test set:

| Metric | Value |
|---|---|
| Images | 11,995 (5,995 real / 6,000 AI) |
| Accuracy | 89.32% |
| AUC-ROC | 0.9597 |
| F1 | 0.8919 |
| Precision | 0.9037 |
| Recall | 0.8803 |
| Specificity | 0.9061 |

At a base threshold of 0.50. The best F1 was obtained at 0.43 (F1 0.8933) and the best balanced accuracy at 0.49. The curve is flat between 0.40 and 0.50, so `0.45` is used as the "suspicious" threshold and `0.70` for "high AI probability". Five real images were skipped for exceeding the pixel limit.

This test set is balanced and the threshold was tuned on the same set; validate with external images before using it in production. To use this checkpoint with `verify.py` or the API:

# CLI
python verify.py photo.jpg --modelo truepixel_v2.pth

# API (PowerShell)
$env:TRUEPIXEL_MODEL_PATH="C:\truepixel\truepixel_v2.pth"
uvicorn api:app --reload

🧪 Per-Generator OOD Validation

Organize external images into `ai_*` folders and run the script to evaluate each generator separately:

C:\datasets\ood\
  real\
  ai_midjourney\
  ai_sd15\
  ai_sdxl\
  ai_flux\

.\evaluar_ood.ps1 -DirReales C:\datasets\ood\real -DirOod C:\datasets\ood -Modelo truepixel_v2.pth

The script generates `resultados_ood\ai_*.csv` (per-image predictions), `ai_*.json` (summary), and `resumen_ood.csv` (comparison). Useful parameters: `-Salida`, `-BatchSize`, `-NumWorkers`, `-Umbral`, `-MaxImagePixels`, `-SinRecursivo`, and `-Python` if the interpreter is not at `.venv\Scripts\python.exe`.

🔎 Local and Batch Verification

`verify.py` accepts a single image, a directory (recursive), or a ZIP:

# Single image
python verify.py photo.jpg

# Directory with CSV output and heatmaps (Grad-CAM + spectrum)
python verify.py ./images --csv results.csv --explicar ./maps

# ZIP with JSON output
python verify.py batch.zip --json > results.json


Each analysis can generate two explanatory images: `*_overlay.png` (regions that most influence the verdict) and `*_espectral.png` (Fourier spectrum).

🌐 Web API Deployment

Once trained, TruePixel includes a FastAPI server so you can query the model from external clients (mobile apps, browser extensions, or moderation backends):

# Start the local API server
uvicorn api:app --reload


Once the server is running, access the interactive documentation at:
👉 http://127.0.0.1:8000/docs

There, you can test the POST /verificar/ endpoint by uploading an image and receiving a structured JSON response:

{
  "archivo": "suspicious_sample.png",
  "probabilidad_ia_porcentaje": 91.43,
  "veredicto": "ALTA PROBABILIDAD DE DEEPFAKE / IA",
  "version_modelo": "3.4.0",
  "version_api": "3.4.0"
}

Available endpoints:

- `GET /health`: service status, device, version, and whether the model is loaded.
- `POST /verificar/`: analyzes an image. Returns `503` if the model is not trained, `413` if it exceeds the size limit, and `415` for unsupported file types.
- `POST /explicar/?tipo=overlay|espectral`: returns a PNG with the Grad-CAM or the Fourier spectrum.

Environment variables:

| Variable | Default | Description |
|---|---|---|
| `TRUEPIXEL_MODEL_PATH` | `truepixel_v1.pth` | Checkpoint path. |
| `TRUEPIXEL_MAX_UPLOAD_BYTES` | `10485760` (10 MB) | Maximum upload size. |
| `TRUEPIXEL_UMBRAL_IA` | `0.70` | "High AI probability" threshold. |
| `TRUEPIXEL_UMBRAL_SOSPECHOSO` | `0.45` | "Suspicious" threshold. |
| `TRUEPIXEL_CORS_ORIGINS` | `*` | Allowed origins, comma-separated. |

Docker deployment:

# Build the image and mount your trained weights
docker build -t truepixel .
docker run -p 8000:8000 -v "$PWD/truepixel_v1.pth:/app/truepixel_v1.pth" truepixel

⚠️ Known Limitations

- **Resize/JPEG confounder:** resizing to 224x224 and JPEG compression introduce high-frequency artifacts that can resemble an AI fingerprint. Train and evaluate with comparable resolution and compression across classes to avoid shortcut learning.
- **The spectrum depends on preprocessing:** the Fourier branch normalizes each spectrum per image and removes the DC component, but changing the pipeline (normalization, size, window) changes the features. Keep preprocessing identical between training and inference.
- **Data, not magic:** verdict quality depends on the dataset. Include real and synthetic images from multiple generators (Midjourney, DALL-E, Stable Diffusion) and evaluate on a separate test split.
